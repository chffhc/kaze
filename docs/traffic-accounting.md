# 流量账务升级与回退

先升面板，再升节点。升级前先停止引入新流量，等待原入口的最后一批收到 ACK；旧面板的去重记录只在内存，不会迁入新库。无法确定最后一批是否已入账时，应先对账，不能把跨升级的第一批视为已验证。使用 SQLite 在线备份或在停止面板后做一致性备份（不要只复制运行中 WAL 库的主文件），同时保存节点状态目录。

新面板兼容旧 `report`。新节点使用独立的 `report_v2`，旧面板不会处理它。不能把新节点连到旧面板当作降级方案。回退顺序是：在新面板仍在线时停入流、排空节点所有已采集和未确认流量并核对面板计数，再停节点，保留整份状态，换回旧节点，最后才回退面板。不要通过删除节点计量状态、清空游标表或恢复收款后的旧数据库来处理卡住的批次。没有对齐两端状态的回滚点时应停止切换，先对账。

面板按入口组、节点 UID 和上报流保存游标。同一批重传只记一次账。游标与规则、用户、设备组和小时统计在同一 SQLite 事务中提交，使用 WAL + synchronous=FULL。小时统计按首次入库时间归集。活动规则使用入库时的倍率。升级至数据库版本 4 后，删除规则或迁移入口会保存原入口的计费快照，旧入口的迟到流量可按快照倍率计入原用户名下。

升级前已经删除的规则可能缺少归属记录。无法归属或数值无效的条目单列在 `traffic_unattributed`，同批有效条目照常入账。管理首页显示近 62 天未归属的条数和流量，超过保留期的明细由后台清理。对账时也应检查日志中的“流量未确认”。保留节点上报游标，以便识别重传。

节点每 5 秒尝试一次落盘，控制连接断开时仍继续采集。待确认批次保持原样，新字节合并到下一批。磁盘写失败或缓冲达到容量时，进程退出可能丢失超过 5 秒的未落盘流量。

更换令牌后，节点通过同一面板认证并确认节点 UID 和设备组与原账本一致，才会续报旧批次。面板、UID 或设备组发生变化，或旧账本缺少确认归属的字段时，节点把待确认流量保存在状态目录的 `kaze-traffic-v2.outbox.<stream>.bak`，供人工对账。卸载前请排空并备份 `kaze-node.json` 和 `kaze-traffic-v2.outbox`。卸载会移除活动账本，并保留已经生成的对账归档。

这是对已持久化批次的保证，不是逐包同步记盘：硬崩溃、磁盘故障或恢复过旧备份仍可能使尚未持久化的实时增量丢失。节点状态目录必须位于可靠、独占、可写的持久卷，不要跨实例复制活动状态。旧节点只有内存待确认批次，即使先升级面板，也不能获得新节点的重启恢复能力。
